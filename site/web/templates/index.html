Python job queue · Redis · asyncio

      

        Jobs that survive the worker running them.
      

      

        Every state change is one atomic Lua script. Every
        running job holds its own lock. When a worker dies
        mid-job, a stalled sweep hands the work to another one. At-least-once, and honest about it.
      


      

        View on GitHub
        Open the live dashboard
      

      

        pip install toro-queue
        MIT · 1.0.0

        A real queue, running on this page
        two workers · concurrency 3 · 4s locks
      

      {% include "partials/pulse.html" %}
    

    

      Kill a worker and it dies the way a crashed process dies: no graceful stop, no released locks.
      Its jobs sit in active until their locks expire, then
      toro's stalled sweep hands them to the survivor and they finish. Nothing is simulated; the
      numbers come from Queue.counts() against Redis.
